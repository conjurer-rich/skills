# Stop, hand-off and the cost note

Read when the **Stop rule** trips: the hand-off threshold (50 % context, 80 main-session tool calls, or a finished Work) or the hard stop (80 %, 150, or three identical isolation-guard refusals); and when a **Run** hands off before waiting on its ticket (**Waiting** in `references/run.md`).

## Run state

The counters live in `run-state.json` in the run's scratch directory: `tool_calls` (the delegator's own calls in the main session; a subagent's calls do not count), `guard_refusals` (keyed by the refused command), `step`, `issue`, `worktree`, `worked_issue` (set once Work opens a PR or goes to **Blocked**), `ticket` (the chain's `{issue, pr}`, **Ticket** in `references/run.md`), `item_start_calls` (the value of `tool_calls` when the current claim won, for the cost note), and the **Session title** state `title` and `ccr_session_id`. The delegator rewrites the file at the start of every numbered step and after every refusal, so a wakeup can read where the stopped run got to without replaying it. Three refusals of the same command mean the command is wrong for this environment, not that a fourth phrasing will pass.

## Stopping

1. **Checkpoint.** At the hand-off threshold, finish the current item to its next checkpoint first: Work runs on to its PR (or **Blocked**); Review, Land and Sync run on to their push, or to their stop without one. At the hard stop, stop at once, leaving staged work in the worktree.
2. **Walkthrough.** Stop any walkthrough stack the run left running.
3. **Hand-off comment.** When the run holds a PR, renew its claim and post one comment on it with `delegate-status comment <PR> --body-file <file>`:

   ```markdown
   <!-- delegator:handoff -->
   **Hand-off** from delegator session `<session>` at <entry point> step <n> (<trigger>).
   - **Done:** <what this session finished, with commit SHAs>
   - **Next:** <the one step the next session runs first>
   - **Verified:** `<command>` → <result, one line each>
   - **Open threads:** <thread or comment ids still needing an answer, or none>
   - **Traps:** <commands or paths that failed and why, so the next session does not repeat them, or none>
   <!-- delegator -->
   ```

   Without a PR (a hard stop before Work opened one), post it on the issue instead, and add the worktree path and what is staged there under **Done**. The comment needs no answer, and `delegate-status pr` returns the latest one as `handoff`: a session that claims the PR next reads it before its first step and does not re-derive what it says. It never replaces the checks: a session re-runs what its own steps require.
4. **Cost note.** For each PR the session worked, `delegate-status cost-note <PR> --tool-calls <tool_calls − item_start_calls>`, adding `--handoff` when this stop hands off. It keeps one entry per session, so writing it again replaces this session's entry.
5. **Release** every claim, with the reason `handed off` or the step reached, and stop each heartbeat. The lease slot waits for **Hand-off**, which hands it on or releases it. The ticket marker stays: the chain keeps its ticket, and the next session renews it.
6. **Report** the step reached, the worktree path, what is staged there and what the next session should do first.

Then continue with **Hand-off**, under `/loop` or not. A run started by hand that finished its entry point (its PR opened, pushed or landed) has nothing to hand on: it ends after **Report**.

## Hand-off

A skill cannot run `/clear` or `/compact`, and a `/loop` wakeup is a new turn in the same session with the same context, so the only way a loop or a run gets an empty context is a new session. A run that trips the **Stop rule**, under `/loop` or started by hand, ends here, handing its command to a new session when it can:

1. **Check.** Hand off only when the `create_session` tool of the `claude-code-remote` MCP server is in the tool list (Claude Code on the web). A **Run** that came here only to hand off before it waits on its ticket (**Waiting** in `references/run.md`) and cannot hand off keeps its lease slot and its loop: it waits in place as **Waiting** says, and skips the rest of this section. A stop on isolation-guard refusals never hands off: the same environment would refuse the same command in the new session. Nor does one when this session was itself started by a hand-off and trips the context or tool-call rule before finishing one pass: a fresh context that fills in one pass would fill again, and the chain would never end. When it does not hand off, `lease release` the slot and clear `lease` from `claims.json`, so a later pass in this session takes a slot instead of renewing the released one. Under `/loop` or in `loop` mode, then skip to step 4, set the **Session title** to `[loop ended] <title>`, and report `loop ended: <reason>; start a fresh session with /loop /delegate`. A run started by hand that does not hand off reports as **Stopping** says and ends. On the CLI, after a finished Work, the loop may instead keep running Watch-only passes in this session (never **Pick**) until the next threshold.
2. **Start the next session.** When the session holds a lease slot, first name the successor with 8 random hex characters, stop the lease heartbeat and `lease hand <id> --to <successor>`, so the new session holds the slot without racing for it and no third session can take it. Then call `create_session` once, counted in `tool_calls`, with `prompt` set to the session's loop command (**Loop command** in `references/watch.md`: `/delegate loop` for `/loop /delegate`, `/delegate loop watch` for `/loop /delegate watch`), never a `/loop` command, which the new session refuses as a relay participant, or, for a run started by hand, the exact `/delegate` command with its arguments (`/delegate #<n>`, `/delegate review #<n>`), `source_url` the main checkout's `origin` URL with no `source_revision`, `outcome_branch` a fresh `claude/delegate-handoff-<8 hex>` that is absent from `origin` (`git ls-remote --exit-code origin refs/heads/<name>` exits 2; pick another suffix otherwise), `title` `/delegate watching <owner>/<repo>`, and `append_system_prompt` set to `Delegator hand-off from session <ccr_session_id> after <trigger> at step <step>; session name <successor>; ticket #<issue> PR #<pr> chain <chain>; subscribe PRs #<a>, #<b>.` The new session takes that session name, so its **Run** step 1 finds the slot already its own. Without a lease slot, or when `lease hand` exits 4 (the slot was already lost), leave out `session name <successor>;`: the new session then takes a slot with `lease take` like any session. `ticket #<issue> PR #<pr> chain <chain>;` copies `ticket` and `chain` from `run-state.json`, without ` PR #<pr>` while its `pr` is null; leave the part out when no ticket is set. The PR numbers are the PRs this session holds (with a ticket, its PR alone) (**Watch** step 6), taken from `subscribed.json` before step 4 empties it; with none, end the line after `<step>.` Pass `environment_id` when the parameter is set; when it is unset leave it out so the new session inherits the environment, and always leave `model` unset so it inherits that. Without `outcome_branch` the new session records no repository, and the sidebar files it under "Other" instead of with this one; the delegator never pushes to that branch, it only names the repository. Do not reuse `ccr-outcome-branch` or a fixed name: the cloud harness's stop hook counts every commit on the default branch that a same-named `origin/<branch>` lacks as unpushed and blocks each turn, and with no such remote branch it compares against `origin/HEAD`, the fresh checkout, and finds none. A session whose system prompt carries that line was started by a hand-off. The new session starts a fresh Run, not the stopped Work. When its hand-off line names a ticket, it writes it to `run-state.json` as `ticket` and resumes that ticket, with `chain` from the line and `ticket_id` from the `ticket` its first status names: it never runs Pick while the ticket is open. After a `/delegate #<n>` it instead works that issue again from **Work** step 1, since the claim was released. Either way it finds the hand-off comment on the PR or issue when it claims it. A call that fails is reported in one line and ends the loop as step 1 says; a slot already handed lapses after `claim_ttl`.
3. **Mark this session.** Set the **Session title** to `[handed off → <id>] <title>`, so the sidebar shows that this session has stopped and which session carries the loop on.
4. **End this session's loop.** Under `/loop` or in `loop` mode, schedule no next pass: under a self-paced `/loop`, call `ScheduleWakeup` with `stop: true`; under an interval `/loop`, delete its job with `CronDelete`; in `loop` mode there is no `/loop` to stop, and cancelling the reminder below ends the loop. Cancel a pending `next_pass_trigger` reminder as **Watch** step 1 does, or it wakes this session after the hand-off and runs a second loop beside the new session's. Stop any background poll and heartbeat, and unsubscribe only the PRs it holds, those in `subscribed.json`, so no event wakes this session again. Step 2 already named them to the new session, which subscribes to exactly those and to no other PR.
5. **Report** as **Stopping** says, plus the new session as a clickable link, `[<id>](https://claude.ai/code/<session id>)`, where `<session id>` is the full id `create_session` returned and `<id>` the same last 8 characters as the title. Do not archive this session: in a cloud container a hard stop's staged worktree lives only in this container, and the report is where the human finds it.
