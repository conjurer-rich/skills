# Watch

One pass over every open delegated PR, built to run under `/loop`. Watch holds no state between passes beyond its session name, its pending next pass and the digest baseline; everything it needs is on GitHub, so a restarted loop loses nothing but waits out its old claims. `/delegate` runs the Watch digest first and reaches this file only when something changed (`references/watch-digest.md`).

1. **Status.** First, whatever woke this pass (the reminder, a GitHub event, a background task or the human), read `next_pass_trigger` from `run-state.json`. When it is set and `next_pass_at` is still in the future, that reminder has not fired: cancel it with `delete_trigger`. Clear both fields either way; a failed delete is reported in one line and never stops the pass. Record the digest baseline (`watch-digest --state <scratch>/delegator/watch-digest.json --record`, plus `--prs-only` for a Watch-only loop) and keep its `next_interval_minutes`. Then run `delegate-status status` (under **Run**, with Pick's `--cache`). Reclaim each `worktrees.reclaim` entry as `references/reclaim.md` says.
2. Its `prs` lists every open PR whose head branch starts with `<branch_prefix>`, oldest `createdAt` first.
3. Each PR carries a `class`:
   - **Claimed** (`claimed`): another session holds a live claim on it (`holder`). Not touched this pass, and never taken over. A PR marked `stale_label` carries `<progress_label>`, and one with no live claim is not Claimed: remove the label as **Stale label** says; its class already ignores the label.
   - **Needs review** (`needs-review`): at least one review thread, top-level comment or review body needs an answer (see **Delegator marker**; the ids are under `needs_answer`), and the PR is a draft or `land` is off.
   - **Ready** (`ready`): `land` is on, `isDraft` is false and `ready` is above 0, counted over the PR timeline's `ready_for_review` events only. That is: the human marked it ready at least once and has not returned it to draft. A PR opened as non-draft has no ready event and is never Ready. `latest` tells Land whether a commit arrived after the last Ready.
   - **Conflicted** (`conflicted`): `mergeable` is false, the PR is neither Ready nor Needs review, and no Sync marker names its current head (`sync_marker.current`). GitHub computes mergeability lazily, so `mergeable: null` is no conflict yet; the next pass sees it. A Needs-review PR that is also conflicted (`conflicted: true`) is reviewed first and synced on a later pass.
   - **Idle** (`idle`): everything else. Never touched.
4. Run **Review** on each Needs-review PR, committing without asking. Then run **Land** on each Ready PR. Then run **Sync** on each Conflicted PR. Work oldest `createdAt` first, one PR at a time. Check the **Stop rule** after each PR: past the hand-off threshold, leave the rest to the next session.
5. Report one line per PR: number, state, and the action taken, `claimed by <session>`, or `idle`. Name idle non-draft PRs so the human sees them. Set the **Session title** to its watching form only if the session has held no item yet; otherwise the last item's title stays.
6. Under a self-paced `/loop`, schedule the next pass `next_interval_minutes` out (10 after a full pass; the digest doubles it per idle pass up to 60); an interval `/loop` reschedules itself:
   - Where the `send_later` tool of the `claude-code-remote` MCP server is in the tool list (Claude Code on the web), call it once with `delay_minutes` set to `next_interval_minutes`, `message` set to the exact `/loop` command this session was started with, `name` `delegate next pass` and `initiation` `own_followup`. Do not also call `ScheduleWakeup`: two schedulers would fire two passes. Write the returned `trigger_id` and `fire_at` to `run-state.json` as `next_pass_trigger` and `next_pass_at`. A `ScheduleWakeup` timer dies with the container when the idle session is reclaimed; the reminder is kept on the server.
   - Otherwise (the CLI), call `ScheduleWakeup` with `delaySeconds` 60 × `next_interval_minutes`.

   Land's review and CI wait run in the background, and the background task that finishes wakes the loop, so a pass never polls to babysit them. To notice a Ready click, a new comment or a CI result sooner:
   - Where the `subscribe_pr_activity` tool of the `claude-code-remote` MCP server is in the tool list (Claude Code on the web), subscribe each delegated PR once, when Work opens it or a pass first lists it, and keep the numbers in `subscribed.json` in the session's scratch directory. Leave no background poll: each GitHub event wakes the session, and the wake runs one Watch pass, except for an event that only echoes a comment carrying the delegator marker. A merge-conflict notice wakes it too. Unsubscribe a PR once it merges or closes.
   - Otherwise leave a background poll running between passes. It checks each delegated PR's draft state, mergeability and unanswered comments, plus any new delegated PR, about once a minute, with `gh api` REST calls only, and exits on the first change. Comments that carry the delegator marker do not count as a change.
