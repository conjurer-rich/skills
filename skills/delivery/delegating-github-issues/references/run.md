# Run

One unattended pass: **Watch**, then **Pick** and **Work**. Built to run under `/loop`, so that one command keeps delegating until it needs the human. Like Watch, it holds no state between passes beyond its session name and its pending next pass. Nobody answers prompts during a Run, so a Run pass never waits on the human: anything that needs an answer stays on GitHub for a later pass.

**Lease.** `delegate-status lease` caps the chains (a Run and the sessions it hands off to) at `max_chains` with the **Claims** protocol, on one tracking issue: the lowest-numbered open issue labelled `delegator-lease`, which `lease take` opens when there is none and the other actions require (`--lease-issue <n>` names another). Each live claim comment on it is a slot, and the first `max_chains` by id hold the slots, so a slot lapses `claim_ttl` after its last heartbeat. `lease take` prints `won` with the `id` and `slot`, reusing this session's slot; with every slot held by a live chain it posts nothing (in a race, withdraws its own claim), prints `full` with the `holders` and exits 5. `lease renew <id>`, `lease heartbeat <id>` and `lease release <id>` work as for a claim; release deletes the comment. `lease hand <id> --to <session>` rewrites the slot to name the successor and renews it, keeping its id and so its rank: the successor's `lease take` finds it already held, and no other session can take it in between (`references/handoff.md`).

1. **Lease.** Before anything else, hold a chain slot, passing `--max-chains <max_chains>` to every `lease` call: when `claims.json` holds a `lease`, `delegate-status lease renew <id>`, and on `lost` clear `lease` from `claims.json` and go on as without one. A slot is lost this way when the loop idled past `claim_ttl`: Claude Code on the web reclaims an idle container, and its heartbeat with it. Without a `lease`, `lease take`, and on `won` keep its `id` as `lease`. Only `full` (exit 5) ends the loop: report `all <slots> chain slots held by <holders>; exiting`, end this session's loop as **Hand-off** step 4 in `references/handoff.md` does, and end the session. Otherwise keep `lease heartbeat <id>` running as a background task for the rest of the session, starting it again when it is not running; when it exits 4, the slot is lost: clear `lease` from `claims.json` and finish the current item to its next checkpoint. The next pass's step 1 takes a slot again, or ends on `full`.
2. **Watch.** Run **Watch** steps 1–4.
3. **Budget.** Read `budget` from the status Watch ran; if Watch reviewed, landed, synced or reclaimed anything, run `delegate-status status --cache <scratch>/pick-cache.json --sync-labels` again first. If `at_limit` is true, skip Pick without commenting: the paused comment would repeat on every pass. Go to step 5.
4. **Pick**, from that same status, unless `worked_issue` is set in `run-state.json`: a session that has worked one issue never picks another (**Stop rule**). Only when Pick returns a candidate, read `references/work.md` and **Work** it, which commits without asking (**Work** step 10). One Run pass works at most one issue through to its PR before the loop reschedules; it never picks a second issue in the same pass, whatever `max_worktrees` allows. Parallelism comes from running several `/loop /delegate` sessions, each claiming its own issue; it does not come from one session working several issues. When Work stops because the issue waits on the human (a question, or criteria awaiting a 👍) or is blocked, the pass goes on to step 5. A later pass picks the issue up once the human answers. A Work that opens its PR, or goes to **Blocked**, has reached the hand-off threshold; so has a pass past 50 % context or 80 tool calls. Such a pass reports, hands the loop off as **Hand-off** (`references/handoff.md`) says, and ends; the fresh session starts a fresh Run.
5. **Report** Watch step 5's lines, then one line for the issue: its number and the outcome (the PR URL, `waiting on the human`, `blocked`, `over budget`, or `no eligible issue` with Pick's `counts`). Set the **Session title** to its watching form only if the session has held no item yet; otherwise the last item's title stays; a pass that stopped at **Blocked** keeps the issue's title.
6. Under `/loop`, schedule the next pass as **Watch** step 6 does, unless the pass tripped the **Stop rule**: then **Hand-off** ends this session's loop instead. The background poll, where Watch runs one, also exits when a `<label>` issue is opened or gains a comment.
