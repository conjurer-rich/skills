# Run

One unattended pass: **Watch**, then **Pick** and **Work**. Built to run under `/loop`, so that one command keeps delegating until it needs the human. Like Watch, it holds no state between passes beyond its session name, its pending next pass and its ticket. Nobody answers prompts during a Run, so a Run pass never waits on the human: anything that needs an answer stays on GitHub for a later pass.

**Lease.** `delegate-status lease` caps the chains (a Run and the sessions it hands off to) at `max_chains` with the **Claims** protocol, on one tracking issue: the lowest-numbered open issue labelled `delegator-lease`, which `lease take` opens when there is none and the other actions require (`--lease-issue <n>` names another). Each live claim comment on it is a slot, and the first `max_chains` by id hold the slots, so a slot lapses `claim_ttl` after its last heartbeat. `lease take` prints `won` with the `id` and `slot`, reusing this session's slot; with every slot held by a live chain it posts nothing (in a race, withdraws its own claim), prints `full` with the `holders` and exits 5. `lease renew <id>`, `lease heartbeat <id>` and `lease release <id>` work as for a claim; release deletes the comment. `lease hand <id> --to <session>` rewrites the slot to name the successor and renews it, keeping its id and so its rank: the successor's `lease take` finds it already held, and no other session can take it in between (`references/handoff.md`). `lease status` needs no `--session` and writes nothing: it prints the `live` and `free` slots and the `holders`, with `lease` null when there is no tracking issue. `scripts/delegate-fire` reads it from a GitHub Actions cron to restart chains that ended (`references/delegate-fire.md`).

**Ticket.** A chain owns one ticket until it is complete. The ticket is `ticket` in `run-state.json`, `{issue, pr}`, beside `chain` (the session name that set it, kept across hand-offs) and `ticket_id`: **Work** under Run sets it when its claim wins, with `pr` null, and records `pr` when it opens the PR or **Blocked** pushes its draft. **Hand-off** carries it to the session it creates (`references/handoff.md`).

The ticket is also recorded on its issue, so it outlives a lapsed lease slot or a reclaimed container: `delegate-status ticket set <n> --chain <chain>` posts a ticket marker comment, `--pr <P>` records the PR on it, and Pick reads an issue whose live marker names another chain as `ticketed` and skips it. Only a marker the delegator's own login posted counts. A marker with a PR lives while that PR is open; one without lapses `ticket_ttl` (12 hours; `--ticket-ttl` changes it) after its last renewal, so while the ticket has no PR each pass runs `ticket renew <issue> <ticket_id> --chain <chain>`, and a long wait keeps `ticket heartbeat` running beside it. The human releases a ticket by deleting the marker. `ticket set`, `renew` and `heartbeat` exit 4 when another chain's marker stands on the issue or this chain's has lapsed: clear `ticket`, stop work on it, and never set it again over the other chain. Pass `--chain <chain>` to every `status` and `ticket` call while `chain` is set. When `ticket` is unset but the status names a `ticket` (a live marker of this chain; on a `delegated` issue `status` reads the comments for it too, and names the open PR), adopt it as `ticket`, with its `pr`, and its `id` as `ticket_id`. A session that stopped before recording its ticket, or lost `run-state.json` with a reclaimed container, resumes its ticket this way, PR or not. A session that lost `run-state.json` takes `chain` from its hand-off line, else its session name.

Each pass refreshes the ticket from the status **Watch** step 1 ran, before Watch step 4; the first case that applies wins. Whenever `ticket` is cleared, `ticket release` its marker; an exit 3 means it is already gone.

- The issue is not in `issues`: it closed, or the human removed `<label>` from it, which is how the human releases a ticket. Clear `ticket`.
- `pr` is set and not in `prs`: it merged or closed. Clear `ticket`.
- `pr` is null and the issue is `blocked`: it was never startable. Clear `ticket`; Pick skips it as before.
- `pr` is null, the issue is not `delegated`, and the issue no longer carries this chain's `ticket_id`: the marker lapsed, another chain took the issue, or the human deleted the marker. Clear `ticket`.
- `pr` is null and the issue is `delegated`: record its `pr`. The ticket is open.
- Otherwise the ticket is open: its PR waits on the human or CI, its issue waits on the human, or another session holds a live claim on it, which is never preempted.

1. **Lease.** Before anything else, hold a chain slot, passing `--max-chains <max_chains>` to every `lease` call: when `claims.json` holds a `lease`, `delegate-status lease renew <id>`, and on `lost` clear `lease` from `claims.json` and go on as without one. A slot is lost this way when the loop idled past `claim_ttl`: Claude Code on the web reclaims an idle container, and its heartbeat with it. Without a `lease`, `lease take`, and on `won` keep its `id` as `lease`. Only `full` (exit 5) ends the loop: report `all <slots> chain slots held by <holders>; exiting`, end this session's loop as **Hand-off** step 4 in `references/handoff.md` does, and end the session. Otherwise keep `lease heartbeat <id>` running as a background task for the rest of the session, starting it again when it is not running; when it exits 4, the slot is lost: clear `lease` from `claims.json` and finish the current item to its next checkpoint. The next pass's step 1 takes a slot again, or ends on `full`.
2. **Watch.** Run **Watch** steps 1–4, refreshing the **Ticket** before its step 4.
3. **Budget.** Read `budget` from the status Watch ran; if Watch reviewed, landed, synced or reclaimed anything, run `delegate-status status --cache <scratch>/pick-cache.json --sync-labels` again first. If `at_limit` is true, skip Pick without commenting: the paused comment would repeat on every pass. Go to step 5.
4. **Pick**, from that same status, unless `worked_issue` is set in `run-state.json`: a session that has worked one issue never picks another (**Stop rule**). While `ticket` is set, the chain never runs Pick: when its issue reads `free`, or `held` with `criteria` and no waiting `reason` (the human answered), read `references/work.md` and **Work** it from step 1; otherwise go to step 5. Only when Pick returns a candidate, read `references/work.md` and **Work** it, which commits without asking (**Work** step 10). One Run pass works at most one issue through to its PR before the loop reschedules; it never picks a second issue in the same pass, whatever `max_worktrees` allows. Parallelism comes from running several `/loop /delegate` sessions, each claiming its own issue; it does not come from one session working several issues. When Work stops because the issue waits on the human (a question, or criteria awaiting a 👍) or is blocked, the pass goes on to step 5. A blocked issue clears `ticket`; one waiting on the human stays the ticket, and a later pass resumes it once the human answers. A Work that opens its PR, or goes to **Blocked**, has reached the hand-off threshold; so has a pass past 50 % context or 80 tool calls. Such a pass reports, hands the loop off as **Hand-off** (`references/handoff.md`) says, and ends; the fresh session starts a fresh Run, which resumes the ticket.
5. **Report** Watch step 5's lines, then one line for the issue: its number and the outcome (the PR URL, `waiting on the human`, `blocked`, `over budget`, or `no eligible issue` with Pick's `counts`). Set the **Session title** to its watching form only if the session has held no item yet; otherwise the last item's title stays; a pass that stopped at **Blocked** keeps the issue's title.
6. Under `/loop` or in `loop` mode, schedule the next pass as **Watch** step 6 does, unless the pass tripped the **Stop rule**: then **Hand-off** ends this session's loop instead. The background poll, where Watch runs one, also exits when a `<label>` issue is opened or gains a comment.

**Waiting.** A pass whose ticket now waits on the human or on CI, after this session ran Work, Review, Sync or Land on it, hands off before it waits, as **Hand-off** (`references/handoff.md`) says, below the **Stop rule** thresholds too: the waiting session carries a short brief, not this session's context. On the CLI, where no hand-off is possible, the chain waits in place instead: it keeps its lease slot and its loop, schedules no next pass, leaves the ticket's background poll running (**Watch** step 6), and while the ticket has no PR keeps `ticket heartbeat <issue> <ticket_id>` running as a background task; the poll's exit wakes it. A session that has only checked its ticket waits in place too, and an event wakes it, never a scheduled pass, except the web's safety-net reminder while the ticket has no PR (**Watch** step 6). Land's pinned CI wait (**Land** step 7) is a step of Land, which keeps its claim through it; the pass hands off after Land ends.
