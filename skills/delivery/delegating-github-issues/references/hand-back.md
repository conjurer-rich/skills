# Hand-back contract

Every subagent writes its full report to a file under the scratchpad directory (or `<worktree>/.delegator/` when no scratchpad is available) and returns to the delegator **at most ten lines**: the file path, a one-word verdict (`pass` / `findings` / `blocked`), and a count or one-line summary. It never returns a diff, a screenshot, a browser snapshot, a test log, or a report body. The delegator reads the file only when it has to decide something and then reads only the verdict table or findings list, never the diff. The delegator never runs `git diff` itself; when it needs to know which files changed it asks the subagent for `git diff --cached --name-only` and nothing more.

The contract applies to every subagent this skill dispatches: bootstrap, implementer, the independent checks, walkthrough, evidence, and the fallback ship subagent below. Unless a step says otherwise, a dispatch is `subagent_type: general-purpose` at its default model with `run_in_background: false`.

**Other harnesses.** The dispatch parameters here (`subagent_type`, `model`, `run_in_background`) are Claude Code's. `references/harness.md` says what each becomes in another harness, or with no subagents at all.

**Self-contained briefs.** A subagent starts from its brief alone. Never fork the conversation into it and never tell it to read this session's transcript: an inherited context made every commit-and-push subagent start at about 60k tokens. The brief carries what the step needs and nothing else: the worktree path, the files to read or write, the exact commands to run with their expected outputs, and for a diff its `--shortstat` line, not its body.

**Cheapest model that can do the step.** Mechanical steps, where the brief names every command, run on `model: <mechanical_model>` (default `haiku`): bootstrap, the evidence push, the fallback ship subagent, and any comment, label or poll a step hands out. Judgement keeps a stronger model. The implementer's model follows the expected tier (**Work** step 4): `<implementer_model_small>` (default `sonnet`) for an expected S, `<implementer_model_large>` (default `opus`) otherwise. A cheap attempt that returns `blocked` or measures not S escalates once to `<implementer_model_large>`, in the same worktree with the attempt's staged changes (**Work** step 6, **Escalation**); it never steps down. Land's review subagent (Land step 5) and Sync's resolution check (Sync step 4) run on `<review_model>` (default `opus`); the checks and the walkthrough run at their default. Label edits, comments and CI polling the delegator does itself, through `delegate-status`, and never dispatches.

**Scratch layout.** One directory per run, `<scratchpad>/delegator/<session name>/`: `run-state.json` (the **Stop rule** counters and the **Session title** state), `claims.json` (**Claims**), `pick-cache.json` (**Pick**), `ccr-session-id` (**Session title**), `subscribed.json` (**Watch**), and per issue `<N>/implementer.md`, `<N>/checks/<check>.md`, `<N>/walkthrough.md`, `<N>/commit-message.md`, `<N>/pr-body.md`, `<N>/ship.log`, and screenshots at `<N>/<surface>-<theme>-<before|after>.png`. The Watch digest baseline, `<scratchpad>/delegator/watch-digest.json`, sits one level up so every run of the session shares it. Every brief names the files it must write. A subagent that writes to GitHub is briefed with `delegate-status`'s absolute path and `--repo`, and makes every write outside git through it.

**Shipping inline.** Commit, push, PR creation and the CI wait are fixed commands, so the delegator runs them itself, from the main checkout, each with its output appended to `<scratch>/<N>/ship.log` so a hook's or a server's chatter never lands in the main context. Each is one command on its own, with no `echo`, loop or pipe, so the command's allowed tools cover it unattended. The tool result's exit status is the verdict; on a failure, read only the last lines of the log (`tail -n 5 <scratch>/<N>/ship.log`):

```bash
git -C <worktree> commit -q -F <scratch>/<N>/commit-message.md >> <scratch>/<N>/ship.log 2>&1
git -C <worktree> push -q -u origin <branch> >> <scratch>/<N>/ship.log 2>&1
git -C <worktree> rev-parse HEAD
```

The PR itself is `delegate-status pr-create`, and the CI wait `delegate-status checks <PR> --head <sha>`, both one JSON line. A push never takes a force flag. If the environment refuses `git -C` (an isolation guard), do not rephrase it: dispatch one ship subagent on `model: <mechanical_model>` instead, briefed with the worktree path, "work only inside `<path>`", the commit message file, the exact three commands above and that each must exit 0; it returns the head SHA, or `blocked` with the failing command's last line.

**The delegator never enters a worktree.** The delegator stays in the main checkout for the whole run. It runs no `git` command inside a worktree other than `git worktree add`, `git worktree list`, `git worktree remove`, `git worktree prune`, `git -C <path> status --porcelain` for Reclaim, and the three shipping commands above (`git -C <path> commit -q -F`, `git -C <path> push -q`, `git -C <path> rev-parse HEAD`). Every subagent that touches a worktree is briefed with the worktree's absolute path and the instruction "work only inside `<path>`". Do not use the Agent tool's `isolation: "worktree"` for these dispatches: it gives the subagent a fresh temporary worktree of its own, not the delegated one, so the implementer's staged work and the push would land in different places. The worktree isolation guard that refused `cd … && git`, heredocs naming git, loops and `agent-browser eval` in the aborted run never fires on a delegator that issues none of them.
